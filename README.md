# MAPS AI Pipeline

준비된 메타데이터와 합성 참조자료를 읽어 표준단어·표준용어 후보를 검색하고,
검증된 추천 결과를 요청별 JSON으로 보존하는 로컬 Python 구현이다.
처리 연결과 상태·판본 관리를 확인하는 기준선이며 실제 매핑 정확도나 생산성을 측정하지 않는다.

## 처리와 경계

입력 읽기 → 계약 검증 → 사전 별칭 검색 → 업무개념·자료형 확인 → 후보 또는 보류 → 출력 검증 → 결과 저장.
적재·Profiling·DQ는 호출하지 않는다. 업무 정의 변경은 같은 메타데이터를 참조하는 새 요청으로 처리한다.

| 항목 | 현재 동작 |
| --- | --- |
| 표준단어 | 컬럼명 전체 또는 밑줄·공백으로 분리한 토큰의 사전 별칭 검색 |
| 표준용어 | 컬럼명 전체와 사전 별칭의 일치 검색 |
| 업무 의미 | 명시된 `concept_id`의 일치·충돌 검증; 자유서술 의미 추론 없음 |
| 표준도메인 | 추천하지 않음; 용어에 연결된 도메인을 그대로 참조하고 자료형 검증 |
| 표준코드 | 추천·생성하지 않음; 연결 도메인의 제공된 허용값만 보존 |
| Target | 제공되고 확정된 구조에서 같은 용어 ID·같은 자료형으로 후보 생성 |
| 모델 | 호출 없음, 모의 응답 없음, `model_used: false` |
| 점수 | 공공표준·업무개념 모두 `null`; 합성사전 일치를 공공표준 점수로 환산하지 않음 |
| 승인·변환 | 구현 범위 밖; 모든 결과는 미검토이며 승인·실행 가능 플래그는 `false` |

사전에 없는 항목은 보류한다. 신규 단어·용어 생성안, 의미 유사도 검색, Target 초안 생성은 아직 구현하지 않았다.
관련 없는 별칭 후보는 충돌 사유와 함께 남긴다. 후보의 `hold_reasons`가 비어 있어도 표준 확정이나 승인 완료를 뜻하지 않는다.

## 구조

| 파일·경로 | 기능 |
| --- | --- |
| `maps_ai_pipeline/contracts.py` | 엄격한 입력 필드·판본·참조 연결·식별자·JSON 검증 |
| `maps_ai_pipeline/adapters.py` | 준비된 입력 읽기와 요청별 결과 저장 경계; 로컬 구현 |
| `maps_ai_pipeline/pipeline.py` | 검색·보류·Target 매핑 후보·출력 무결성 검사 |
| `maps_ai_pipeline/__main__.py` | 모듈 실행 CLI와 종료 코드 |
| `examples/synthetic/` | 재추천·Target 미제공을 포함한 완전한 합성 입력 |
| `tests/test_pipeline.py` | 후보·보류·판본·재실행·동시 저장·잘못된 입출력 검증 |
| `docs/contract.md` | 입력·출력·상태 계약 |
| `docs/local-run.md` | Windows PowerShell 실행 방법 |

## 결과 보존

결과는 `local-results/<customer_id>/<project_id>/<batch_id>/<request_id>.json` 하나에 저장된다.
파일에는 입력 문서 전체 스냅샷, 입력 내용 지문, 추천 결과와 판본이 함께 들어간다.
임시 파일 기록·flush·fsync 후 배타적인 hard-link 생성으로 완성본을 발행하며 기존 파일을 덮어쓰지 않는다.
NTFS 등 hard link를 지원하는 로컬 파일시스템이 필요하다.
미완료 임시 파일은 결과로 읽지 않는다. 프로세스 강제 종료로 남은 임시 파일의 자동 복구·정리는 구현 범위 밖이다.

같은 범위·같은 요청 ID·동일 입력·동일 처리 판본은 기존 결과를 재사용한다.
같은 ID에 다른 입력을 주면 충돌하며 기존 결과를 보존한다.
업무 정의 변경은 새 판본·새 요청 ID로 저장한다. 동일 판본명 내용의 변경도 입력 지문에 반영된다.
단, 프로젝트 전체의 판본명 불변성을 강제하는 중앙 참조 등록부는 구현하지 않았다.

## 검증 범위와 한계

Python 3.11 이상, 런타임 외부 의존성 없음. 설치나 API 키 없이 모듈 실행이 가능하다.
표준 라이브러리 `unittest`로 핵심 처리·거부 사례를 검증한다. 실행 명령은 [로컬 실행 안내](docs/local-run.md)를 따른다.

자료형은 `string`, `integer`, `decimal`, `date`, `datetime`, `boolean`의 정규화된 여섯 종류만 지원한다.
길이·정밀도·nullable·키·변환식·복합 매핑·실제 코드값 대응·행 단위 DQ는 검사하지 않는다.
제공된 코드 허용값은 참조일 뿐 실제 데이터값의 검사 완료를 뜻하지 않는다.
모든 샘플은 이 구현을 위해 만든 합성이며 공공표준·고객 표준의 공식 항목을 재배포하지 않는다.

ADLS·OneLake·SQL DB·Dataverse·Fabric·실제 모델 연결은 없다.
후속 연결에는 읽기·조건부 저장 어댑터, 고객별 권한, 판본 등록부, Backend 수신 중복 방지,
승인 대상 판본 고정과 기존 변환 엔진 계약을 별도로 맞춰야 한다.
로컬 파일 무결성 검사나 입력 지문은 사용자 인증·권한 격리를 대신하지 않는다.

## 외부 참조사전 읽기 경계

`python -m maps_ai_pipeline.reference_check --dictionary`와 `--output` 인수로 외부 사전을 읽기 전용 검사한다.
합성 추천 파이프라인과 별도인 참조사전 어댑터다. 외부 사전 원본을 프로젝트에 복사하지 않는다.
검색 활성 단어·용어만 이름·영문약어로 검색하고 활성 용어의 도메인 ID·이름 연결을 검사한다.
동일 약어의 모든 후보는 업무 의미 미검증으로 보류한다. 도메인·코드 추천은 지원하지 않는다.
결과는 집계만 기록하며 출력 파일이 이미 있으면 덮어쓰지 않고 거부한다.
자체 조회 검사는 사전 구조·검색 연결 검사이며 독립적인 매핑 정확도 평가가 아니다.
이 어댑터의 단위 테스트는 합성 형식 자료로 실행한다. 실제 외부 사전 실행과 구분한다.

## 외부 사전으로 추천 실행

`python -m maps_ai_pipeline.external_run`은 `--dictionary`, `--bindings`, `--request`, `--output`을 받는다.
기존 추천·출력 검증·요청별 저장 흐름에 외부 참조사전 선택 어댑터를 연결한다.
`examples/external/`에는 합성 메타데이터, 업무 정의 두 판본, 명시적 개념 연결 규칙과 요청 두 개가 있다.
별칭으로 검색된 활성 단어·용어와 연결 도메인만 메모리에서 정규화하며 원본을 수정하지 않는다.
원문에 없는 용어–단어 연결은 빈 목록으로 두고, 코드 허용값은 파싱·생성하지 않는다.
명시적 규칙이 없는 참조 항목의 개념 ID는 null이다. 미지원 도메인 자료형도 null로 두어 후보 적용을 보류한다.

업무 규칙의 개념 ID와 사전 용어명을 명시적으로 연결한 합성 규칙 실험이다.
이는 독립 정답 평가나 자유문 의미 이해가 아니며 모델을 호출하지 않는다.
원문 자료형의 정규화만 지원하며 길이·정밀도·nullable는 여전히 검증 범위 밖이다.
사전 판본명은 요청자가 부여한 로컬 스냅샷 표식이며 공식 배포본 판본 확인을 뜻하지 않는다.
요청의 dictionary.path는 이 어댑터에서 메모리 선택본의 논리 이름이며 읽기 경로는 CLI로 전달한다.
결과에는 선택한 참조 항목과 업무 규칙 전체를 함께 보존한다. 선택되지 않은 원본 레코드는 복제하지 않는다.
원본 전체의 판본 불변성은 별도 참조 등록부가 필요하다.

패키지 구성과 Azure 연결 전 결정할 사항은 [실행·배포 경계](docs/deployment-boundary.md)에 정리했다.
현재 클라우드 배포는 구현·검증하지 않았다.
